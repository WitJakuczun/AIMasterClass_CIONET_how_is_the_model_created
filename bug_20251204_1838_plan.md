# Fix "Unknown field for Schema: default" Error Implementation Plan

## Overview
The Gemini API integration is failing with `Error selecting model: Unknown field for Schema: default`. This is caused by the inclusion of the `"default"` key in the function parameters schema defined in `chatml/function_schemas.py`. The Gemini API schema validation does not support this field; default values should be handled by the backend logic and described in the `description` field to guide the model.

## Current State Analysis
- **File**: `chatml/function_schemas.py`
- **Issue**: The `visualize_comparison` tool definition includes `"default": "f1_macro"` and `"default": "backtesting"`.
- **Impact**: The `GeminiConnector` fails to initialize the `genai.GenerativeModel` because of this schema violation.
- **Backend Support**: `mlops/app.py` defines `visualize_comparison` with default arguments (`run_type="backtesting"`, `metric="f1_macro"`), so the backend is already prepared to handle missing parameters.

## Desired End State
- `chatml/function_schemas.py` is updated to remove `"default"` keys.
- The application initializes successfully without schema errors.
- The `visualize_comparison` tool works correctly, using backend defaults when parameters are omitted by the model.

### Key Discoveries
- `chatml/function_schemas.py`: Invalid `default` keys present.
- `mlops/app.py`: `visualize_comparison` method has Python-level defaults, ensuring safety when parameters are omitted.

## What We Are NOT Doing
- We are not changing the logic of `visualize_comparison` in `mlops/app.py`.
- We are not adding `default` support to other tools unless they are also broken (none found during inspection).

## Implementation Approach
1.  Modify `chatml/function_schemas.py` to remove the `default` keys from `visualize_comparison`.
2.  Verify the fix by initializing the `GeminiConnector` (using a simple script or the existing `main.py` if appropriate).
