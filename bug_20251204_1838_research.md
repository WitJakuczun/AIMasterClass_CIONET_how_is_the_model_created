## Research: Fix "Unknown field for Schema: default" error

**Summary**
The error `Error selecting model: Unknown field for Schema: default` is caused by the inclusion of the `"default"` key in the parameter definitions for the `visualize_comparison` tool in `chatml/function_schemas.py`. The Google Gemini API's function declaration schema does not support the `default` field; default values should instead be handled in the application logic and described in the `description` field.

**Detailed Findings**
- **`chatml/function_schemas.py`**: The `visualize_comparison` tool definition includes `"default": "f1_macro"` for the `metric` parameter and `"default": "backtesting"` for the `run_type` parameter.
- **`chatml/gemini_connector.py`**: The `GeminiConnector.get_model` method initializes the `genai.GenerativeModel` using these schemas. The library validation fails when it encounters the unsupported `default` field.

**Code References**
- **`chatml/function_schemas.py`**:
  ```python
  "visualize_comparison": {
      # ...
      "parameters": {
          "type": "OBJECT",
          "properties": {
              # ...
              "metric": {
                  "type": "STRING",
                  "description": "...",
                  "default": "f1_macro"  # INVALID FIELD
              },
              "run_type": {
                  "type": "STRING",
                  "description": "...",
                  "default": "backtesting"  # INVALID FIELD
              }
          },
          "required": ["experiment_id"]
      }
  }
  ```

**Architecture & Patterns**
The application defines function schemas in a dictionary and passes them directly to the Gemini SDK. The schema format must be strictly compatible with the API's expectations. The current pattern of including `default` values in the schema is incorrect for this API.

**Conclusion**
To resolve the bug, the `"default"` keys must be removed from `chatml/function_schemas.py`. The descriptions already correctly inform the model about the default values ("Defaults to 'f1_macro'", etc.), which allows the model to omit these parameters, letting the backend handle the defaults.
