# Fix Visualization Data Loading Plan

## Overview
The `visualize_comparison` function in `mlops/app.py` fails to generate charts because it expects a `results.csv` file, while the backtesting runner (`mlops/runner.py` via `ResultStore`) saves results to `results.json`. This mismatch causes the function to return an error message, leading to a "silent failure" experience for the user.

## Current State Analysis
- **Producer**: `mlops/runner.py` uses `mlops/result_store.py` to save metrics.
- **Storage**: `ResultStore` saves data to `artifacts/experiments/<id>/<type>/results.json`.
- **Consumer**: `mlops/app.py` (`visualize_comparison`) looks for `results.csv` or glob `*backtesting*.csv`.
- **Outcome**: `visualize_comparison` finds no files and returns a string error.

## Desired End State
- `visualize_comparison` correctly loads data from `results.json` using `ResultStore`.
- Data is correctly transformed from the JSON structure (nested dicts) to a Pandas DataFrame.
- The chart is generated successfully when valid data exists.

### Key Discoveries
- `mlops/result_store.py`: `save_metrics` uses `json.dump`.
- `mlops/app.py`: `visualize_comparison` uses `pd.read_csv`.

## Implementation Approach
Modify `mlops/app.py` to prioritize loading from `ResultStore` (`results.json`). Keep the CSV loading as a fallback (or remove it if legacy support isn't needed, but I will keep it for robustness).
