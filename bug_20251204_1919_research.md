## Research: Brak pliku z wykresem po wywołaniu `visualize_comparison`

**Summary**
Funkcja `visualize_comparison` w `mlops/app.py` działa poprawnie pod kątem logiki kodu, ale nie wygenerowała wykresu, ponieważ w katalogu eksperymentu brakuje wymaganych danych wejściowych (pliku z wynikami backtestingu). Funkcja zwróciła komunikat o błędzie jako string ("Nie znaleziono wyników dla exp001 / backtesting"), który prawdopodobnie nie został wyświetlony przez interfejs czatu, co użytkownik zinterpretował jako brak reakcji ("neither text nor a function call").

**Detailed Findings**

1.  **Logika funkcji `visualize_comparison` (`mlops/app.py`)**:
    - Funkcja najpierw sprawdza istnienie katalogu eksperymentu.
    - Następnie próbuje zlokalizować plik z wynikami. Domyślnie szuka `artifacts/experiments/exp001/backtesting/results.csv`.
    - Jeśli plik nie istnieje, uruchamia mechanizm *fallback*, przeszukując rekurencyjnie katalog eksperymentu w poszukiwaniu pliku CSV zawierającego w nazwie `run_type` (w tym przypadku "backtesting").
    - Jeśli żaden plik nie zostanie znaleziony, funkcja zwraca string: `Nie znaleziono wyników dla {experiment_id} / {run_type}`.
    - Jeśli dane zostaną wczytane, ale DataFrame jest pusty, zwraca: `Brak danych do wizualizacji.`

2.  **Stan danych (`artifacts/experiments/exp001/backtesting/`)**:
    - Badanie struktury katalogów wykazało, że katalog `artifacts/experiments/exp001/backtesting/` istnieje, ale jest pusty (nie zawiera pliku `results.csv`).
    - Katalog nadrzędny `artifacts/experiments/exp001/` również nie zawiera plików pasujących do wzorca fallback (`*backtesting*.csv`).

3.  **Interpretacja braku odpowiedzi**:
    - Kod `visualize_comparison` zwraca komunikaty błędów jako zwykłe stringi (np. `return f"Nie znaleziono wyników..."`).
    - Log użytkownika: `The model returned a response containing neither text nor a function call` sugeruje, że connector (`GeminiConnector` lub warstwa wyższa) mógł nie obsłużyć poprawnie zwrotu wartości typu string z funkcji narzędzia, lub model po otrzymaniu komunikatu o błędzie (jako wyniku funkcji) nie wygenerował odpowiedzi tekstowej dla użytkownika.

**Architecture & Patterns**
-   **Fail-fast with strings**: Funkcje narzędzi w `app.py` zwracają komunikaty błędów jako stringi zamiast rzucać wyjątki. To jest dobra praktyka dla interakcji z LLM (model otrzymuje informację zwrotną o błędzie), ale wymaga, aby LLM po otrzymaniu takiego wyniku wygenerował odpowiedź dla użytkownika.
-   **Data Dependency**: Wizualizacja jest ściśle zależna od artefaktów generowanych w poprzednich krokach (backtesting). Brak pliku `results.csv` wskazuje, że etap backtestingu nie zakończył się poprawnie zapisem zagregowanych wyników lub używa innej konwencji nazewniczej niż ta oczekiwana przez wizualizator.

**Conclusion**
Wykres nie powstał, ponieważ w systemie brakuje pliku z wynikami (`results.csv`) dla eksperymentu `exp001` w trybie `backtesting`. Funkcja zadziałała poprawnie, identyfikując brak danych i zwracając odpowiedni komunikat tekstowy. Problem leży w braku danych wejściowych (kwestia wcześniejszego etapu pipeline'u) oraz potencjalnie w sposobie, w jaki interfejs czatu prezentuje wynik funkcji, który jest prostym komunikatem błędu.
